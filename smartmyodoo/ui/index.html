Architektura Bezpieczeństwa & Dokumentacja

🤔 Jak i dlaczego to działa?

Skarbiec opiera się na kryptografii wielowarstwowej z tzw. Key Encrypting Key (KEK). Zamiast szyfrować dane bezpośrednio Twoim hasłem, system generuje losowy, super-silny klucz główny (Vault Key) algorytmem AES-128-CBC (Fernet). Następnie ten Vault Key jest w locie dwukrotnie kopiowany i szyfrowany osobno: raz przez Twój 4-cyfrowy PIN (w pliku .pin_key), a drugi raz przez długie Master Password (w pliku .master_key).

✅ Co jest w pełni BEZPIECZNE?

  • Hasła leżące na dysku: Plik .vault_data to kompletny bełkot kryptograficzny. Nawet jak haker wykradnie cały folder smart_vault (wraz ze wszystkimi solami i kluczami), bez poprawnego PINu lub Master Password nie zrekonstruuje klucza głównego i nie odczyta nawet jednej litery.
  • Bezgłośny Schowek: Kopiowanie hasła w GUI pomija konsolę systemową. Kliknięcie używa natywnego Clipboard API w przeglądarce, maskując wartości gwiazdkami. AI podglądające terminal nie ma szans na przeczytanie kopiowanego hasła.
  • Izolacja ENV w Dockerze: Komenda python vault.py run docker-compose up wstrzykuje sekrety do środowiska powłoki jako zmienne w locie, dzięki czemu Twoje pliki `docker-compose.yml` pozostają wolne od wycieków z na sztywno wpisanymi tokenami.

⚠️ Co NIE JEST bezpieczne (Na co uważać)?

  • Zgubienie OBU poświadczeń: Zgubienie PINu to żaden problem (zresetujesz go używając Master Password). Jednak zapomnienie Master Password przy jednoczesnej utracie PINu oznacza TRWAŁĄ I BEZPOWROTNĄ utratę dostępu do wszystkich haseł. Kryptografia AES-128 nie ma "tylnej furtki".
  • Działający serwer GUI w tle: Skarbiec API działa na protokole HTTP (localhost:5050). Ogranicza go to do komunikacji lokalnej, ale złośliwy program na Twoim komputerze mógłby teoretycznie odpytać port 5050 gdy panel jest odblokowany. Dlatego zalecamy używać opcji Zablokuj Sejf lub ubijać terminal w IDE po zakończeniu pracy, co zamyka okno autoryzacji.
